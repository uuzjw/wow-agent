## 旧方式的痛点

- **上下文丢失** — 编辑器和聊天之间反复复制粘贴
- **无法执行** — AI 不能跑测试、不能验证更改
- **你是桥梁** — 每段代码都要手动集成
- **没有防护** — 建议直接应用，无法撤销

## wow-agent 的方式

| 原则 | 实现 |
|---|---|
| Agent 而非 Assistant | 在你的代码库执行真实操作 |
| 本地优先 | 零遥测；本地模型完全离线可用 |
| 模型无关 | 16+ 云端服务商 + Ollama/LM Studio |
| 默认安全 | 沙盒、外传拦截、确认机制、回滚 |
| 可扩展 | MCP 协议 + 自定义工具 + 子代理 |

## 对比

| 差异 | 传统工具 | wow-agent |
|---|---|---|
| 模型 | 锁定单一厂商 | 任意 OpenAI 兼容 API |
| 运行环境 | 绑定 IDE / 云端 | 纯终端 |
| 架构 | 仅 x86 | 原生 ARM64 |
| 安全 | 直接执行命令 | 沙盒 + 回滚 |

> **一句话**：模型选择权、环境控制权、安全决策权。
