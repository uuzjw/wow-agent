跟踪一个请求 —— *"修复 src/config.py 里的重复键 Bug"* —— 看它穿过整台机器。
## 全路径
```text
你
 │ "修复重复键 Bug…"
 ▼
┌──────────────────────── CLI (cli.py) ────────────────┐
│ 解析输入 → 路由：对话？命令？Shell 直通？             │
└──────────────────────┬───────────────────────────────┘
                       ▼
┌───────────────── 智能核心 (agent.py) ────────────────┐
│ 1. 加载记忆 (/mem) + 会话上下文                       │
│ 2. 查代码索引找相关符号                               │
│ 3. 让模型出计划 → 任务树 (todo.py)                    │
│ 4. 状态：PLANNING → 展示计划 → 批准？                 │
└──────────────────────┬───────────────────────────────┘
                       ▼ 计划批准
┌──────────────────── EXECUTING ───────────────────────┐
│ 对每个子任务：                                        │
│   模型选择 工具 + 参数                                │
│        │                                             │
│        ▼                                             │
│   ┌─ 安全门 (tools.py) ───────────────────┐          │
│   │ Schema 校验 → 外传模式 → 高危检查      │          │
│   │ → 需要确认？                           │          │
│   └──────────────┬────────────────────────┘          │
│                  ▼                                   │
│   快照 (undo.py) → 执行工具                          │
│                  ▼                                   │
│   结果回传模型（有界输出）                            │
└──────────────────────┬───────────────────────────────┘
                       ▼ 子任务全部完成
┌──────────────────── VERIFYING ───────────────────────┐
│ 通过 Shell 工具跑测试 + Lint                          │
│   通过 → DONE（总结、更新记忆）                       │
│   失败 → FAILED → 自动回滚任务全部快照                │
└──────────────────────────────────────────────────────┘
```
## 逐跳细节
### 1. 上下文组装
任何模型调用前，大脑先组装：系统提示词 + i18n 文案 + 对话 + 记忆条目 + 针对目标关键词的**代码索引命中**。索引命中意味着模型读到的是 `config.py` 的符号大纲，不是整个仓库。
### 2. 规划调用
模型返回任务树（JSON）。`todo.py` 校验依赖并存起来。自动模式跳过批准门 —— 高危步骤之后仍会单独确认。
### 3. 工具选择循环
每轮迭代：模型输出 `{tool, params}` → Schema 校验 → 安全门 → 快照 → 执行。结果（截断，如最后 2000 字符）作为工具消息返回。循环直到模型表示完成或到达 `WOW_MAX_ITER`。
### 4. 安全门的顺序
```text
参数校验 ──▶ 外传模式 ──▶ 高危模式 ──▶ 确认
   │               │              │            │
 400 类           拦截/记录       拦截/记录      输入 YES
```
顺序有讲究：便宜的检查在前；确认在最后，只给幸存者。
### 5. 快照
`undo.py` 在写入前对目标文件做 Diff，把 `{元数据, Diff}` 存到 `~/.wow-agent/snapshots/`，并关联当前任务 ID。任务失败时按逆序回放任务关联的快照。
### 6. 验证
Shell 工具运行你项目的测试（自动探测：pytest/npm test/go test…）。非零退出 → 验证失败 → 回滚 + 附带失败命令输出的错误报告。
## 什么会碰网络？
| 环节 | 联网？ |
|---|---|
| 模型 API 调用 | 是 —— 只发给你选的服务商 |
| 工具执行（沙盒内） | **否** —— 命名空间隔离 |
| MCP 服务器 | 继承沙盒 |
| 遥测 | 不存在 |
## 故障遏制
任何一层失败都不会破坏状态：模型错误 → 重试/下一轮；工具错误 → 回传模型自我纠正；验证失败 → 回滚；进程崩溃 → 会话与快照落盘保留。
